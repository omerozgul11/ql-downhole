# Testing

Run suites one at a time (`dotnet test tests/<project>`); `scripts/build.sh` runs them all.

| Project | What it covers |
|---|---|
| `DownholeStudio.SignalProcessing.Tests` | FFT (radix-2 and Bluestein) against a direct DFT; Butterworth low/high/band-pass and notch magnitude responses, causal and zero-phase filtering against SciPy golden values (`golden-scipy.json`, regenerated by `generate_golden_scipy.py`); detrend; shifts; AGC; taper; envelope; correlation lag recovery; resampling and anti-aliasing; rotation |
| `DownholeStudio.Formats.Tests` | SEG-2 round trips for every encoding and byte order; committed golden files; malformed files (truncated, wrong id, missing descriptor, pointer outside file, missing sample interval, invalid terminator, 20-bit and unknown encodings); dates; import validation messages; depth/shot suggestions |
| `DownholeStudio.Analysis.Tests` | Hand-calculated formulas (slant distance, vertical time, interval velocity, Vs30, extrapolation rules, Poisson, G, E, K and their equivalent forms, invalid cases, Gardner, Brocher, unit conversions, trigger correction modes); regression and Huber robustness; Snell's-law tracer vs independent Fermat timer; pickers; SNR; confidence explanations; polarization; correlation; layer suggestions |
| `DownholeStudio.Core.Tests` | End to end on synthetic SEG-2: import → geometry → automatic picks → velocities for all four methods vs the true model; trigger errors corrected; reversed polarity; missing traces reported not invented; noisy data; Vs30 refusal and labelled extrapolation; quality verdict; save/load round trip (byte-identical raw data); backups; damaged files; undo/redo of every edit type; gestures; manual vs automatic picks; scenarios; recovery; catalogue; PDF/XLSX/CSV/audit export |
| `DownholeStudio.Licensing.Tests` | Token signing/verification and tampering, key format, envelopes, fingerprint normalisation and SMBIOS parsing, encrypted store, offline activation (computer codes, keys bound to one computer, tampering, expiry and clock rollback, no network), the managed P-256 verifier cross-checked against the platform, licence state machine (trial, expiry, licence, offline grace, network validation, clock rollback, revocation, activation limit, server unreachable, deactivation, device change) |
| `DownholeStudio.IntegrationTests` | Licence server and admin portal against a real PostgreSQL 17 container with the real client: the full licensing validation list, Stripe webhooks, update feed, admin flows and audit |
| `DownholeStudio.UiTests` | Headless Avalonia with Skia rendering, driving the real views and view models. `WorkflowTests`: the full survey from offline activation to report. `FeatureAcceptanceTests`: every user-facing command on every page, asserting real outcomes (files with correct signatures and sizes, undo restoring state, raw data unchanged, read-only mode without a licence). `RenderThreadTests`: every chart painted on a background thread, as desktop platforms do. `UpdaterTests`: signed update manifests and tampered installers. Set `DHS_SCREENSHOTS=<folder>` to keep screenshots of every step |

Explicit tests (run on request with `-- xUnit.Explicit=only`, and `DHS_CUSTOMER_UI=1` to show the application exactly as shipped, without a licensing server): `ProductScreenshots` renders `docs/images` for the README and brochure; `TrainingCapture` captures the training-video frames (see [marketing/training](marketing/training/README.md)).

## Windows
`.github/workflows/windows-tests.yml` runs on real Windows machines (GitHub Actions). It catches what Linux cannot, such as Windows refusing to delete an open file.

- **`suites`** runs on every push: every test suite and the scientific validation. It fails on any failed or skipped test.
- **`customer`** runs on `ci/*` branches. `tests/windows/customer-acceptance.ps1` does what a customer does: it downloads the published package, checks it, installs it and operates the application with real mouse and keyboard input. That covers activation, typing, the Windows file dialogs, import, picking, reports, Excel export, saving, crash recovery, restart and uninstall.

The customer job needs an activation key for its machine, which exists only for that run. It publishes the machine's code to the branch `ci-results/<run id>-customer` as `computer-code.txt`, then waits up to 25 minutes for `key.dhslic` on the branch `ci-key/<run id>`. Issue the key from a short-lived licence in the admin portal. The branch `ci/final` downloads from `main`, which proves the public links; other `ci/*` branches test their own copy of the files. Delete the `ci-*` branches afterwards.

## Browser test environment
`testenv/start.sh` runs the real Linux build of the application, the licence server, the admin portal, a mailbox and a file browser in Docker, all usable from a web browser. Unlike the headless tests, it renders on a real render thread. See [testenv/README.md](testenv/README.md).

## Synthetic datasets
`src/DownholeStudio.Synthetics` generates SEG-2 surveys with known Vp, Vs, depths, offsets, trigger
delays and noise: Clean, Noisy, MissingTraces, TriggerErrors, ReversedPolarityS. Arrival times come
from a Fermat-principle ray timer that is independent of the engine's Snell's-law tracer.

## Scientific validation
`dhs validate --out docs/validation` writes the validation report (input, expected, actual,
difference, tolerance, result for every check). See [SCIENTIFIC-VALIDATION.md](SCIENTIFIC-VALIDATION.md).
